# Enefit source gate

Enefit's [Kaggle competition data](https://www.kaggle.com/competitions/predict-energy-behavior-of-prosumers/data) is an **Estonian prosumer dataset**, separate from the BDG2 US/Central whole-building benchmark and the OpenCEM campus microgrid. Its page lists CC BY-NC-SA 4.0; competition rules also apply. The owner reports non-commercial use and prior rules acceptance, but local account access and downloaded files remain to be verified. Do not publish source rows or model artifacts until their redistribution terms are reviewed.

The source dictionary says all dataset times are EET/EEST. Target `datetime` is the **start** of a one-hour interval. Some forecast-weather values describe the interval's end even though `forecast_datetime` names its start. `forecast_weather.csv` contains weather available at prediction time: `origin_datetime` and `hours_ahead` must be honoured to prevent leakage. `surface_solar_radiation_downwards` is Wh/m² accumulated during the hour; `client.installed_capacity` is kW. The public description calls `train.target` the hourly production/consumption **amount**, but this audit does not assume a kWh unit until source evidence is checked against downloaded files and documentation. Never combine Enefit timestamps, sites, or target labels with BDG2 buildings.

After signing in and downloading `train.csv`, `forecast_weather.csv`, and `client.csv`, place them under `backend/local_data/enefit/` (Git ignored). From `backend/`, run `uv run --locked python scripts/audit_enefit.py --data-dir local_data/enefit` when the project's `uv` environment is available. The audit streams CSV rows, checks required columns, finite nonnegative core values and forecast availability, reports missing/invalid timestamps and DST-sensitive local hours, and prints SHA-256 hashes, counts, local time ranges, and a quality gate. It does **not** train a model. Keep the source report privately until licence and data quality review is complete.

Training can begin only after source access, target-unit verification, DST-safe interval alignment, source-specific weather/client joins, and a chronological holdout design are verified. The trained model must forecast **Enefit production for its own population**; any use to estimate output at a Malaysian demo site is a separately labelled transfer assumption, not validation at BDG2 or Sime Darby. BDG2 remains the demand-model source. Dispatch stays constrained and read-only. Measured savings remain unavailable without a documented action and post-action observations.
